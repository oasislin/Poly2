> **数据支撑**：Dune Analytics 链上公开订单簿与交易事件库、Allium 预测市场微观结构研报、学术与量化团队公开数据

## 1. 核心论点与研究背景

在量化交易系统工程中，最大的认知陷阱是**“闭门造车假想敌人”**——许多团队误以为自己在与顶级做市商（如 Citadel、Jump Trading）争夺纳秒级的微波光纤专线，从而把系统设计得神经过敏，塞满了脱离现实的毫秒级超时与死锁。

本报告通过穿透真实链上数据与市场微观结构，得出以下**不可动摇的商业与工程定论**：
1. **盘口极其微型，巨头不屑入场**：Polymarket 单一城市日最高温盘口的日交易量通常仅在 **1 万 ~ 6 万美元**，根本无法支撑大型 TradFi 高频量化机构数千万美元的专线与服务器开销；
2. **散户占人头，算法占体量**：全平台呈现剧烈的极化特征——80% 以上的活跃钱包是资金量在 $10k 以下的散户，但 75% 以上的名义交易量由自动化机器人提供；
3. **假想敌是“看手机 App 的散户”与“被动铺单的做市商”**：盘口的真正对手盘是信息延迟达数十分钟的手工下注散户，以及只赚买卖价差（Spread）但对物理突变反应迟钝的做市机器人；
4. **分钟级是降维打击，秒级是物理现实**：我们不需要毫秒专线。我们依靠的是**“ASOS 官方原报 0.1°C 高精解码 + 高斯 EMOS 物理分布”**，在公网 5~10 秒级工程公差下，在分钟级周期上相对散户建立碾压级的确定性信息与定价优势；
5. **订单必须碎化**：由于真实流动性极浅，策略必须“小步快跑、碎单蚕食”，严禁大单冲击盘口。

## 2. 链上实证数据透视 (Empirical Microstructure Data)

根据 Dune Analytics（如 `polymarket_volume`、`dune.polymarket.dataset`）对 Polymarket 链上真实事件的统计审计，平台真实微观结构呈现以下硬核特征：

### 2.1 用户数与交易量的“极化二八法则”

| 指标维度 | 散户群体 (Retail Traders, 资金 < $10k) | 自动化脚本 / 做市商 / 大户 (Bots & Whales) |
| :--- | :--- | :--- |
| **独立活跃钱包数占比** | **80% ~ 88%**（绝对大多数） | 12% ~ 20% |
| **名义成交量占比 (Notional Volume)** | 仅占 **15% ~ 25%** | **垄断了 75% ~ 85%** |
| **单笔下单金额中位数 (Median Size)** | **$15 ~ $120**（极度零碎的长尾博弈） | $2,000 ~ $50,000+（大额挂单铺设流动性） |
| **长期盈亏分布** | 超过 85% 的散户钱包处于长期净亏损 | 前 1% 的账户赚走了全平台 **75% 以上的净利润** |

### 2.2 天气（Weather）短周期垂直盘口的特定数据
在日内短周期（Short-duration / Daily Closes）温度市场中：
- 自动化的 Bot 交易量占总量的 **55% ~ 62%**；
- 散户交易笔数占比达 **35% ~ 45%**，但由于单笔下注极小，资金体量占 **15% ~ 25%**；
- 单一温度档位（如 `86-87°F`）的订单簿静态挂单深度（L2 Bid/Ask Depth）通常只有 **$300 ~ $2,500**。

## 3. 市场四大核心玩家画像（谁在真正买卖筹码？）

在一个典型的全美 Active 10 交易站点（如芝加哥 KORD、纽约 KLGA、亚特兰大 KATL）的温度市场中，盘口里的筹码交换由四类截然不同的玩家构成：

```
                ┌────────────────────────────────────────────────────────┐
                │          Polymarket 每日温度市场订单簿 (CLOB)           │
                └───────────────────────────┬────────────────────────────┘
                                            │
           ┌─────────────────┬──────────────┴───────┬──────────────────┐
           ▼                 ▼                      ▼                  ▼
┌──────────────────┐ ┌──────────────┐      ┌─────────────────┐ ┌──────────────┐
│  加密投机散户    │ │ 生态做市机器人 │      │ 粗糙脚本搬砖客  │ │ 空投刷量工作室│
│  (Crypto Degens) │ │  (Spread MMs)│      │ (Amateur Arbs)  │ │ (Wash Traders│
│                  │ │              │      │                 │ │              │
│ • 手机端看App    │ │ • 双向被动铺单│      │ • 爬网页HTML比价│ │ • <0.05垃圾档│
│ • 延迟 30~60min  │ │ • 只赚点差   │      │ • 缺乏RMK高精度 │ │ • 左右手互倒 │
│ • 情绪化追涨杀跌 │ │ • 物理突变迟钝│      │ • 极易被反向打劫│ │ • 虚假无风险 │
│ • 单笔 $20~$200  │ │ • 挂单深度浅 │      │ • 15~30min延迟  │ │ • 不影响实盘 │
└──────────────────┘ └──────────────┘      └─────────────────┘ └──────────────┘
```

### 3.1 加密原生“日内高频博弈散户（Crypto Degens）”
- **心理机制**：政治大选盘动辄锁定数月，很多加密用户极度渴望“日内下注、当晚结算、快速周转”的标的，天气盘是全平台极少数“24 小时必开奖”的纯硬核盘口；
- **决策工具**：绝大多数使用 iPhone 自带天气、Weather.com 或推特讨论，这些数据源存在 **30 ~ 60 分钟的严重中继延迟**，且只展示粗放的整点预报；
- **下注特征**：单笔下注小（$20 ~ $200），但人数多、容易在午后气温上升或突发天气新闻时产生情绪化追逐。

### 3.2 官方与生态做市商（Automated Market Makers / AMM & Limit Bots）
- **商业模式**：依赖 Polymarket 官方流动性激励（Liquidity Mining）补贴，主要使用官方开源库 `py-clob-client`，在行权区间双向挂单（如 Bid 0.45 / Ask 0.55）赚取买卖价差；
- **致命弱点**：**他们不预测天气，只根据历史成交价做固定点差被动铺单**。当真实物理世界发生突发特报（SPECI）或冷锋骤降时，这部分机器人的挂单调整存在分钟级迟钝，**正是我们通过市价单（Taker）主动捕获的最佳流动性来源**！

### 3.3 粗糙的脚本搬砖客（Amateur Arbitrageurs）
- **特征**：个人开发者编写的粗糙比价脚本（如在 Kalshi 与 Polymarket 之间搬砖）；
- **弱点**：通常只爬取 NOAA 网页前端的粗糙华氏度整度数，**没有能力解析 ASOS 原报中 `RMK T` 组 0.1°C 精度数据**，且经常被网络限频，带着 15 ~ 30 分钟的老数据挂单，极易被我们系统逆向选择。

### 3.4 空投刷量工作室（Wash Traders）
- 长期在胜率极高（>0.95）或极低（<0.05）的无风险垃圾档位用大额资金对倒，试图博取潜在治理代币空投。这部分交易量巨大，但由于局限在无风险边缘档位，对中间核心价格带的真实博弈几乎零干扰。

## 4. 商业本质与系统时延量纲的重新定型

### 4.1 核心 Alpha 来源：分钟级降维打击
- **信息差梯次**：
  1. 机场 ASOS 传感器发布真实观测（$T_0$）
  2. **我们系统通过 IEM 专线/高频原报捕获并完成 0.1°C 解码（$T_0 + 5\sim15\text{s}$）**
  3. 做市商机器人根据盘口成交感知价格变动（$T_0 + 1\sim3\text{min}$）
  4. 民用气象 App 更新整点瓦片数据（$T_0 + 30\sim60\text{min}$）
  5. 普通散户打开手机 App 追高下注（$T_0 + 45\sim90\text{min}$）
- **结论**：**在 $T_0 + 15\text{s}$ 到 $T_0 + 3\text{min}$ 的这扇黄金窗口期内，我们拥有不可动摇的先发优势！**

### 4.2 物理时延回归工程现实（秒级取代毫秒级）
- 系统运行于普通公网，公网 RTT 正常在 50ms ~ 200ms。加上 TLS 握手与 API 抖动，真实通信是以“秒”计量的；
- **废除虚假毫秒级幻想**：将系统响应基准与看门狗公差统一定在**秒级（5 ~ 10 秒级工程公差）**。这不仅完全足以跑赢对手，更从物理上消除了频繁重试与假报警振荡。

## 5. 对 Phase 2 策略与资金管理的决定性指导

根据上述微观结构，Phase 2 执行引擎必须严格落地以下三条纪律：

### 5.1 订单必须碎化（Staged / Iceberg Taker Orders）
- **严禁大额直接下注**：单个档位有效挂单深度仅有几百到一千多美元。单笔大额下注（如 $3,000）会瞬间击穿订单簿，产生高达 20%~40% 的灾难性滑点；
- **碎单蚕食原则**：执行引擎单笔市价下单额度严格控制在 **$50 ~ $300** 区间，小步快跑分批吃进，动态监测订单簿价格深度。

### 5.2 坚决不市价反向抛售自残
- 在流动性极度匮乏的市场中，一旦出现数据异常，若市价恐慌平仓，由于盘口缺乏买家，市价单会被打到底部垃圾档位，造成巨额亏损；
- 确立持有到期与交割日策略接管原则（对齐 ADR-0012 与 ADR-0014）。

### 5.3 下单前“绝对新鲜度 + 连通性”双硬门禁
- 策略引擎准备下达市价买单的最后 1 秒，必须强制通过：
  ① 数据物理时间戳 $\Delta t_{\text{age}} \le 7\text{min}$；
  ② 数据接入与交易网关确证双连通；
- 杜绝在网络重试期间拿着过期数据盲盒开仓。

## 6. Phase 2 实盘验证假设与数据埋点清单 (Empirical Edge Audit)

Phase 2 上线实盘时，系统必须内置以下专项目标指标，用于正面回答核心商业拷问：

| 验证假设 | 实盘实证指标 (Metric) | 达标检验标准 / 判定门槛 |
| :--- | :--- | :--- |
| **假设 1：散户对手盘与迟钝做市商是否存在？** | 真实成交对手钱包特征分类 (Counterparty Wallet Profiling) | 链上反查确认：至少 30% 以上的成交对手方为散户 EOA 地址或做市商被动挂单合约。 |
| **假设 2：有效流动性深度到底有多大？** | L2 盘口在合意价格下的最大可吃深度 (Executable Depth @ Target EV) | 统计实测每档平均深度是否能稳定容纳 $\ge \$200$ 的单次下单。 |
| **假设 3：分钟级时间窗口是否足够安全？** | 极值报文发布至盘口价格彻底收敛的时间差 (Alpha Half-Life $\tau$) | 实测中位数窗口 $\tau \ge 90\text{s}$，证明 5~10 秒级系统具有绝对先发优势。 |
| **假设 4：扣除摩擦成本后是否存在净胜率？** | 扣除 Polymarket 动态费率后的实际净已实现盈亏 (Net Realized PnL) | 实际净 ROI 显著高于先验气候学基准，且平均单笔滑点控制在 $\le 1.5\%$。 |
