## 3. 归桶语义分析（round_to_nearest_6h 与名义极值）

### 3.1 partitioner.py 的输入语义
- **名义发生时刻**：`TMAX = 15:00 LT`, `TMIN = 06:00 LT`。
- **连续 lead 计算公式**：`lead_hours = (nominal_local_dt.astimezone(UTC) - init_00Z_utc).total_seconds() / 3600.0`。
- **离散归桶**：`round_to_nearest_6h(lead) = int(np.round(lead / 6.0) * 6.0)`。

### 3.3 关键观察与规避陷阱

1. **美洲站点的投影位移**：
   - 东八区（ZSPD，UTC+8）D+0 15:00 LT 对应 07:00 UTC -> 归桶为 6h；
   - 但美洲站点（UTC-4 至 UTC-8）D+0 15:00 LT 发生在起报日晚间至次日凌晨 UTC（19:00 UTC ~ 23:00 UTC） -> 归桶为 **18h 或 24h**！
   - 对应 D+1 归桶为 **42h 或 48h**，D+2 归桶为 **66h 或 72h**。
2. **DST 切换带来的 6h 跨桶漂移**：
   - 例如中部时区（Chicago KORD）：冬季 UTC-6，D+0 TMAX 为 21.0h -> 归桶 **24h**；夏季 UTC-5，D+0 TMAX 为 20.0h -> 归桶 **18h**（因 20/6=3.33，round 为 3 -> 18h）！
   - 这铁证了 **ADR-0008 D4（时区与节点自适应）** 的绝对必要性：任何静态硬编码 {6, 30, 54} 都会在美洲站点的夏冬令时交界处导致致命的特征对齐错位！
3. **完全包含规则（subseteq）的窗口特征**：
   - 美洲各站每个本地日能够完全包含 3 个或 4 个 6 小时窗口；
   - 全池在 D+0 / D+1 / D+2 的包含窗口总并集精确收敛在上述权威采购清单中，下载调度器必须按全量并集统一抓取。
4. **留出节点法（中位节点）奇偶性实测验证**：
   - 跨 D+0、D+1、D+2 三日，各站各季节的自适应基础节点序列严格为 **3 个节点**：
     - **TMAX 序列**：冬季为 `[24h, 48h, 72h]` 或 `[18h, 42h, 66h]`（如 KORD 冬季为 24/48/72，KLGA 冬季为 18/42/66）；夏季相应平移；中位节点必然唯一确定为中间节点（48h 或 42h），由前后两节点（如 24h & 72h、18h & 66h）插值重建；
     - **TMIN 序列**：全池 12 站无论冬夏，三日基础节点恒定为 `[12h, 36h, 60h]`（严格 3 个节点）；中位节点必然唯一确定为 36h，由 12h & 60h 插值重建；
   - 证明：在实际 D+0..D+2 评测视界内，基础节点序列长度恒为奇数（N=3），《项目方案 (v2.6)》§4.2 规定的“留出节点 = 中位节点”数学上严格单值存在，不存在偶数集合中位数歧义。
