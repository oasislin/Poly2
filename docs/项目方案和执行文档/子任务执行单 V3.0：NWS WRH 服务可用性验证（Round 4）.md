## 2. 四项探测实验：实证回答可用性核心命题

### 探针 1：WRH 留存窗口实测（Retention Window Boundary）
- **目标**：实测 WRH timeseries 接口的历史数据回溯留存边界（过去假设 7~14 天，未实测）。
- **实验设计**：
  - 对 ZSPD 以 `units=metric` 与 `units=english` 发起历史回溯请求；
  - 逐步尝试 7、14、30、60、90、365 天前的日期参数；
  - 记录每次请求返回的实际最早观测时间戳与返回条数；
- **输出结论**：确定留存窗口的真实边界天数。这直接决定我们能否一次性对账 30 天，还是必须依赖每日增量归档累积。

### 探针 2：字段精度审计（Field Precision Audit & F1 修复）
- **目标**：审计 `data/raw/nws_wrh/` 已归档的 metric 探针原始 payload，消除隐式取整。
- **实验设计**：
  - 统计接口返回逐时次温度与当日极值的真实小数位数（整数 or 一位小数）；
  - 对比 english 探针的原始华氏度整数，逆向确认是否存在代码内部未声明的取整步骤；
  - 若存在取整，显式移出 `NwsWrhAdapter`，在明细 CSV 中增加 `temp_nws_cal_max_raw_precision` 列记录原始精度，并重算逐日对比（仅重算数值，不重跑统计拟合）。

### 探针 3：抓取稳定性量化（Scraping Stability & Uptime Metrics）
- **目标**：把 14 天运行经验转化为可量化的线上 SLA 硬指标。
- **实验设计**：
  - 在 `NwsWrhAdapter` 增加结构化日志与度量收集：
    - 连续抓取成功率（成功数 / 总请求数）；
    - 失败原因分类（超时 Timeout / 反爬 403 / 鉴权 401 / 空响应 Empty / 解析失败 ParseError）；
    - API 响应耗时分布（P50 / P95 延迟）；
    - 接口字段漂移检测（Schema Drift）：对每次响应的 JSON key 集合进行 diff，出现新增/消失字段立即报警；
  - 汇总指标至 `data/processed/nws_wrh_uptime_metrics.csv`，每日增量追加。

### 探针 4：更新时延与断流监测（Update Latency & Gap Distribution）
- **目标**：评估数据上线时效性与时序完整性。
- **实验设计**：
  - 记录观测时间戳与数据在 WRH 上可拉取时间戳的时延分布（回答"临盘前能否拿到近实时实况"）；
  - 统计 ZSPD 半小时时序在 24 小时各时段的缺测分布（分析缺测是集中在固定夜间时段还是全天随机发生）。
