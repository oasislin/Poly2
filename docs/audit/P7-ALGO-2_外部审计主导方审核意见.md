## 一、P0 级（3/3 属实，全部接受修正）

### P0-1：S6 反向 NO 轨公式 —— ✅ 属实（两份文档各有一个错误，且互不一致）

**原文核对**：
- 《工程落档细化》§3.5 轨 B（L382）：`sum(1 - P_bar,i) >= 1 + margin_dutch (转为互补买入)` —— **与专家引文逐字一致**；
- 《算法描述文档》§9.1（L193）：`Ask(YES_i) + Ask(NO_i) ≤ 1 − m_dutch` —— **与专家引文一致**，且两公式确实不同。

**数学验证**：
- 轨 B：K 档互斥市场 $\sum_i (1-\bar P_i) = K - 1$。K=11 时恒 ≈10，`≥ 1+margin_dutch` 恒成立 → **每 Tick 误判暴利套利**。数学错误成立；
- §9.1 单档配对：用裸 Ask、漏 q_eff 费 ✅ 属实；但专家"恒不成立"论断**需限定前提**——仅在 YES/NO 严格镜像簿（Ask(NO_i)≡1−Bid(YES_i)）下成立；NegRisk 市场中 NO_i 是独立 token，价格可偏离 1−YES_i（这正是套利来源），含费版本仍可触发。专家修正方案自保留此式，与前述"恒不成立"存在轻微自相矛盾，文档落定时需注明适用前提。

**修正方案（采纳，公式需精确化）**：
- 废除轨 B 错误不等式；
- 全包 NO 轨：$\sum_i q_{\text{eff}}(\text{Ask}(\text{NO}_i)) \le (K-1) - m_{\text{dutch}}$（保底赔付 K−1 ✅ 数学正确）；
- 单档配对（含费、注明 NegRisk 独立簿前提）：$q_{\text{eff}}^{\text{YES}_i} + q_{\text{eff}}^{\text{NO}_i} \le 1 - m_{\text{dutch}}$；
- 统一两份文档表述。

### P0-2：内层 argsort 贪心非光滑折角 → SLSQP 高频 Fail-Closed —— ✅ 属实，修正方案数学严谨

**原文核对**：《算法描述》§5（L132）`π = argsort(W_i)`；《工程落档细化》§4.2（L501-514）argsort+贪心填充；§4.3（L588-595）外层 SLSQP 未传 jac（有限差分）——**全部属实**。

**数学验证**：
- 凹函数逐点下确界在极点切换处 C0 非 C1 ✅（inf 保凹但不保光滑）；$W_i(f)=W_j(f)$ 超平面上 argsort 翻转 → 数值梯度跳变 → SLSQP 线搜索失败（status=8）→ G7 Fail-Closed 全零。**风险定性准确**（后果是"安全但放弃本可盈利交易"的假死，非爆仓）；
- LP 强对偶展开：内层 $\min_p \sum p_i\ln W_i(f)$ 是标准 LP（对 p 线性、盒约束+等式），强对偶成立；$\max_f \min_p = \max_{f,\lambda,\alpha,\beta}$ 合并为单层——**标准鲁棒优化对偶化技巧，数学方向正确**；变量 3K+1（K=11→34）、约束 K+1，SLSQP 可行；约束 $\ln W_i - \lambda - \alpha_i + \beta_i \ge 0$ 是凹函数上水平集（凸集），目标线性 → 凹最大化于凸集 ✅ 可闭式 Jacobian。

**修正方案（采纳）**：以 LP 对偶展开替代内层 argsort 贪心；**落文档时对偶公式须精确化推导**（专家给出的 λ+Σp_L α_i−Σp_U β_i 形式经推导存在常数项系数差异，由开发端按标准对偶推导定稿）；规格书 §3.3 引理 1~3 需同步改写为对偶化表述。

### P0-3：下单漏费 / safe_capacity 截断缺失 / eps 未定义 —— ✅ 3/3 属实

**原文核对（全部属实）**：
1. **漏费**：《工程落档细化》§3.4 Step c（L349）`raw_shares = f_i* / P_protect` 与 §六 Step c（L754）`raw_shares = f_i / p_protect` 均用纯盘口价；L354 `lock_funds(final_shares * P_protect)` 不含费——**属实**（协议另扣 `C×0.05×p(1−p)` → 实际扣款超预算或入账股数不足）；
2. **截断缺失**：《算法描述》§8.1（L177）`S_raw = min(f_dec / P_limit, safe_capacity)` **有截断**；《工程落档细化》§3.4 **无截断**——两文档不一致，属实；
3. **eps 未定义**：《工程落档细化》§4.3 L562/L571/L582 使用 `eps`，函数签名（L529-539）无该参数——**NameError 属实**。

**修正方案（采纳）**：①下单股数按含费成本折算：`raw_shares = f* / q_eff(P_protect)`，`lock_funds(final_shares × q_eff)`（含费锁定）；②工程落档细化补 `min(..., safe_capacity)` 截断，对齐算法描述 §8.1；③签名补 `eps: float = 1e-7`。

## 二、P1 级（4/4 属实，2 项需裁决）

### P1-1：S1 target_allocation 鸡生蛋 —— ✅ 属实（需新增规格）

**核对**：《算法描述》§2.1（L35-37）按 $S_{\text{target}}$ 穿透但**未定义取值**；《工程落档细化》§3.1（L217）签名要求 `target_allocation` 但无来源定义——属实。

**处理**：需新增规格：S1 定价探针规模取值规则（候选：`max(min_order_size, min(safe_capacity_at_min_edge, 单档合理探针规模))` 或达标深度 VWAP）。**属新增规格，需用户/主导方定稿后落文档**。

### P1-2：τ 后置乘法 vs 前置预算 + evaluate_all_gates 缺 G3/G4 —— ✅ 属实（架构级调整，需裁决）

**核对**：规格书 §3 管线（L44）S2→S3（τ 在 S3 后置）；《算法描述》§7（L155-156）G3 τ_z∈{1.0,0.5,0.0,0.0}、G4 CRITICAL 0.20x / CERTAIN 禁反向——定义存在；《工程落档细化》§5 evaluate_all_gates（L657-711）**确实只有 G6/G5/G7/G1/G2，缺 G3/G4**——属实。

**数学验证**：凹目标下"先求 f* 再乘 τ" ≠ "预算先缩 τ 再求 f*" ✅；小额订单被 minimum_order_size 团灭场景真实 ✅。

**处理**：**接受前置化建议**：$C_{\max} := \tau_z \cdot \tau_{\text{2D}} \cdot \min(0.10 B_{\text{eff}},\; 0.70 B_{\text{eff}}-\text{Active\_locked},\; W_{\text{free}})$。但注意：规格书 §3（L72）"折剪点唯一化：宪法硬顶与调制全在 S3 实施"是**已冻结架构原则**——前置化将 τ 移入 S2 预算，**触及该冻结条款，需用户裁决**后同步改规格书；evaluate_all_gates 补齐 G3/G4（若采前置化则 G3/G4 转为"预算调制"而非门禁布尔，语义需重新定义）。

### P1-3：G2 分母 B_eff vs Total 不一致 —— ✅ 属实（口径需裁决）

**核对**：《算法描述》§3.2（L80）用 `0.70·B_eff − Active_locked`；§7 G2（L154）与《工程落档细化》§5（L700）用 `Total`（含 Zombie/Disputed）分母——**三处不一致，属实**。

**关键补充**：ADR-0012（L78）原文定的是 `Utilization = Active Locked / Total Bankroll ≤ 0.70`，**Zombie/Disputed 从分子剔除**——即 ADR 本身用 Total 分母。但规格书 §4 M5（L81）"Zombie 0.0x 剔除"精神更接近 B_eff 审慎口径。**矛盾存在于 ADR 与规格书之间**，需用户裁决：统一 B_eff（更审慎，符合 M5 精神）或明确 Total 分母+分子剔除 Zombie 的 ADR 口径（注意 Total 分母含 Zombie 会放松约束）。

### P1-4：并发 FAK 缺腿 + 禁 SELL 死锁 —— ✅ 属实（需定阈值）

**核对**：S6 并发 FAK（契约/开发端审阅已定）+ 宪法禁 SELL + ResidualHealer 仅"30s 平价愈合"无亏损容忍——属实；补单价跳涨 → Σq_eff>1 锁定亏损场景真实。

**处理**：采纳 `max_rehedge_loss` 追单贴水上限（≤2% 允许贴水补单锁死敞口；超阈值 STOP_LOSS_TRIGGERED/LIQUIDATED）。**阈值数值 `[待标定]`（2% 为建议初值，需裁决）**。

## 三、P2 级（3/3 属实，均为文档/字段级修正）

### P2-1：°C/°F 温标硬编码 —— ✅ 属实
规格书 §1（L14）`2°F 档位`、《算法描述》G4（L156）`3°F / 0.5°F` 硬编码；DecisionContext（《工程落档细化》L101 起）**无 temperature_unit 字段**——属实。
**处理**：MarketMeta 增 `temperature_unit: Literal["F","C"]`；G4 阈值按温标换算（3°F↔1.67°C）**或更优：改用标准化残差 $z=|\Delta T|/\sigma_{\text{EMOS}}$（无量纲，规避温标问题）**——方案二选一，建议后者，需裁决。

### P2-2：Delta Method L1 vs L2 —— ✅ 属实（口径说明缺失）
《算法描述》§4.1 /《工程落档细化》§4.1 用 L1 绝对值相加；《数学溯源地图》归源为标准 Delta Method（Casella&Berger / van der Vaart）——**口径说明缺失属实**（L1 是盒式最坏相关上界，比标准独立 L2 传播最多放大 √2 倍，为防御 μ/σ 相关性）。
**处理**：数学溯源地图补注说明；非公式错误，不改公式。

### P2-3：station_tz 缺失 + W_free 基底批注 —— ✅ 属实
MarketMeta 仅 `end_date_iso`（L101），**无 station_tz**——属实（NWS 日极值按站点当地时、DST 特殊规定）。W_i 以 W_free 为基底（《算法描述》L72）——属实，属**刻意设计**（内生降杠杆，Active 高时自动保守）。
**处理**：MarketMeta 增 `station_tz: str`；算法描述 §3.1 加设计意图批注，防开发端误当 Bug。
