### 2. 我方撤回的部分（此前挑战有误，正式撤回）

我方曾在《外部审计报告逐条挑战分析》中指出贵方"同一二元市场 YES/NO 共享镜像订单簿，恒有 Ask(NO_i) ≡ 1−Bid(YES_i)，单档配对除非倒挂否则不可能触发"的论据**不成立**，理由是"YES/NO 为独立 token、独立订单簿、NegRisk 组合 token 可系统性偏离"。

**该反驳经后续验证是错误的，现正式撤回。** 撤回依据：

- **协议层面**：Polymarket 的 split/merge 机制以**固定汇率 $1/对**运作（1 pUSD ⇄ 1 YES + 1 NO，链上操作，不经订单簿），即"1 份 YES + 1 份 NO ≡ 1 pUSD"是**协议硬约束**，直至结算前恒成立——轨 C 从铸造那一刻起就是恒等式；
- **结算层面**：NegRisk 多档市场规则为"**only one outcome can win**"（互斥穷尽），结算赔付总和恒等于 1——轨 A 的 Σ=1 是**概率公理**；
- **实证层面**：真实盘口验证见下（§三），单档 Ask(YES)+Ask(NO) 与跨档 ΣAsk(YES) 均 ≥ 1 + 摩擦，无套利窗口。

### 3. 最终共识：三轨套利全部废除

| 轨 | 定义（含费判定） | 不可能触发的性质 | 依据 |
| :--- | :--- | :--- | :--- |
| **轨 A** 全包 YES | Σq_eff(Ask(YES_i)) ≤ 1 − m_dutch | **公理性不可能** | Σp=1 概率公理；盘口总和被套利均衡钉在 ≥1+摩擦（实测 1.017）＞ 触发线 ~0.98 |
| **轨 B** 全包 NO | Σq_eff(Ask(NO_i)) ≤ (K−1) − m_dutch | **镜像冗余** | 互补恒等下 ΣAsk(YES)+ΣAsk(NO)≡K，"ΣNO≤K−1−m"⟺"ΣYES≥1+m"，与轨 A 同一约束的代数镜像，不增加独立信息 |
| **轨 C** 单档配对 | q_eff(YES_i)+q_eff(NO_i) ≤ 1 − m_dutch | **机制性恒等** | split/merge 固定 $1/对（1 YES+1 NO≡1 pUSD），Ask(YES)+Ask(NO) ≥ 1+spread；套利机器人 split+merge 秒级闭合 <1 窗口 |

**附加判定（为什么不留作"防御"）**：永不触发的判定逻辑留在代码中**只承担误触发 bug 的风险、不产生任何收益**——轨 B 错误不等式即为实例：设计为"套利检测"的代码，公式一旦出错即每 Tick 误判并真实下单。**因此三轨全部移除，不保留死代码。**

### 4. S6 模块处理（项目方已裁定：保留只读错价监控）

三轨全废后，S6 DutchBookScanner 的**自动套利判定整体移除**；**保留只读错价监控**（项目方裁定，2026-10-19）——规格如下：

- **观测对象**：①单档互补偏离 Ask(YES_i)+Ask(NO_i) − 1；②跨档总和偏离 ΣAsk(YES_i) − 1（两处均为相对协议恒等式的偏离度）；
- **频率**：低频轮询（如 60s）或行情事件驱动，计算成本极低；
- **输出**：偏离度时序 + 超阈值告警日志（仅供人工/审计消费）；
- **硬约束**：**不触发任何下单、不产生仓位、不进入交易管线**——纯观测记录；
- **用途**：市场健康度信号（流动性断裂/撮合异常的度量依据），并入风控观测（M 层）；为平台规则未来变化时重新评估套利留数据基础。

## 二、贵方报告中与 P0-1 相关的两处表述，我方立场

1. **贵方"恒有 Ask(NO_i) ≡ 1−Bid(YES_i)"的论据**：结论（单档配对几乎不触发）**成立**，但论据表述"撮合层镜像订单簿强制"仍不准确——真实机制是**链上 split/merge 固定汇率 + 结算公理 + 套利机器人**共同保证，而非撮合引擎镜像。此点仅为表述层面的严谨性建议，不影响贵方结论；
2. **贵方修正方案给出的"全包 NO 轨（对标 K−1）"与单档配对式**：公式数学上均正确，但按 §一.3 的推演——全包 NO 轨是轨 A 的代数镜像、单档配对是机制性恒等、全包 YES 是公理性不可能——**三者均不构成可触发的套利通道，我方判定全部废除，不进设计文档**。
