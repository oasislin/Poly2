## 一、算法定位

P7-ALGO-2 是交易引擎的核心决策算法：**给定 EMOS 概率层的每档概率估计与 Polymarket 盘口，决定"买什么档、买多少、用什么价格买"，并以"只买不卖、向前对冲、本金保护优先"贯穿全链路。** 概率层（F-2）与交易层（本规格）严格分层：本规格消费概率层输出，不参与概率生成。

一句话：**EV 决定方向，凯利决定规模，风控决定放行，执行决定价格。**

## 二、端到端算法流程（7 阶段管线）

```
【上游】EMOS 概率层（F-2 门禁管辖）            【外部】Polymarket CLOB 盘口 / NWS 结算
        │ 每档概率 p̂ (含截断)                        │ 每档 ask/bid 深度
        ▼                                            ▼
┌──────────────────────────────────────────────────────────────────────┐
│  S1 定价与信号（Pricing）     每档有效成本 q_eff（费率/滑点穿透）→ EV / edge → 可交易信号  │
└───────────────────────────────┬──────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────────┐
│  S2 凯利 Sizing（Kelly）      多项互斥档位对数财富增量最大化；旧持仓自然对冲；稳健化防御  │
└───────────────────────────────┬──────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────────┐
│  S3 风控闸门（Risk Gates）    预算硬顶（单市场10%/全局70%）；两维风控；预购门；台站仲裁    │
└───────────────────────────────┬──────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────────┐
│  S4 执行路由（Execution）     保护价计算 → IOC 限价单 → 成交/残差愈合 → 资金锁解            │
└───────────────────────────────┬──────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────────┐
│  S5 持仓与资金（Bankroll）    四桶账务；旧持仓注入下一轮；僵尸双轨估值；持仓绝缘            │
└───────────────────────────────┬──────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────────┐
│  S6 套利通道（Arbitrage）     独立于凯利的无风险扫描：Dutch Book / 跨档锁利 / 对冲豁免登记  │
└──────────────────────────────────────────────────────────────────────┘
                                ▼
┌──────────────────────────────────────────────────────────────────────┐
│  S7 结算与验证闭环（Settlement & Calibration）  结算复刻；纸面盘/回测；两步标定（挂 F-2 锁） │
└──────────────────────────────────────────────────────────────────────┘
```

**横切层（贯穿 S1~S7）**：异常治理（Incident 总线、本地硬阀、紧急停止、台站生命周期）。

## 三、模块清单与职责

| # | 模块 | 核心职责 | 主要输入 | 主要输出 | 核心算法问题 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| M1 | **定价引擎（Pricing）** | 把盘口深度折算为可成交成本，生成交易信号 | 每档 ask 深度、模型概率 p̂、费率参数 | 每档 q_eff、EV、edge、是否可交易 | 深度穿透怎么算？动态费率怎么进 EV？带旗资产怎么降级？ |
| M2 | **凯利优化器（Kelly Sizing）** | 互斥档位间的预算分配（本规格核心） | 每档 p̂、q_eff、有效资金、旧持仓 | 每档目标金额 x* | 目标函数形态？旧持仓如何自然对冲？概率不确定如何防御（稳健化）？ |
| M3 | **风险闸门（Risk Gates）** | 对 x* 施加不可谈判的宪法约束与可标定的调整 | x*、账户状态、台站/临盘状态 | 批准分配 x_approved | 哪些约束是宪法级（10%/70%/预购门）？哪些是 F-2 锁的标定对象？ |
| M4 | **执行路由（Execution）** | 把 x_approved 变成受保护价的 IOC 限价单 | x_approved、盘口、台站状态 | 订单、成交、残差处置、资金变更 | 保护价怎么定？非原子单（部分成交）如何愈合？市价单如何杜绝？ |
| M5 | **资金账务（Bankroll）** | 四桶资金恒等与全链路 Decimal | 订单、结算、僵尸判定 | 余额、锁解、估值 | 双轨估值口径（sizing 0.0x / NAV 折价）？僵尸分级熔断？ |
| M6 | **套利通道（Arbitrage）** | 独立于凯利的无风险机会扫描与锁利 | 全档 bid/ask、持仓成本 | 套利动作、豁免登记 | 无风险机会与凯利如何共存（独立通道）？豁免如何经中枢登记？ |
| M7 | **结算复刻（Settlement）** | 按法定真值源复刻结算并回笼资金 | NWS WRH、持仓、结算时钟 | 结算结果、资金回笼 | 舍入口径？12h 僵尸触发？逾期处置？ |
| M8 | **标定与验证（Calibration/Sim）** | 纸面盘/回测/两步标定，产出参数 | 纸面盘运行记录、历史结算 | 参数建议（θ 等）、门禁报告 | 标定对象是什么？数据从哪来（纸面盘自产）？时序防泄漏？ |

**横切**：异常治理中枢（M-G）——Incident 契约、台站生命周期（ACTIVE/SUSPENDED/INVALIDATED/EMERGENCY_HALT）、本地硬阀、预购双硬门禁。

## 四、数据流与接口要点（模块间传递什么）

1. **S1 → S2**：每档 `(p̂, q_eff, tradable_flag)`——不可交易档不进凯利（EV 过滤前置）
2. **S2 → S3**：目标金额向量 `x*` + 优化器内部状态（是否收敛、是否退化）
3. **S3 → S4**：批准金额 `x_approved` + 门禁通过证据（供审计）
4. **S4 → S5**：成交明细（档位、股数、均价、成本）→ 更新四桶
5. **S5 → S2（回环）**：当前持仓（沉没成本 payout 向量）作为下一轮凯利的外生输入——**"向前对冲"的机制载体**
6. **S6 ⇄ S5**：套利动作占用资金/产生持仓，但**不进入凯利目标函数**
7. **S7 → S8**：纸面盘运行记录与结算结果 → 两步标定的数据源（等纸面盘自产，M-5）
8. **横切 M-G**：任何模块异常 → Incident 上报 → 台站状态变更 → 回灌 S3/S4 门禁

## 五、顶层业务原则（框架级，细则由这些原则派生）

| # | 原则 | 表述 | 出处/依据 |
| :--- | :--- | :--- | :--- |
| P1 | **概率是唯一 Alpha 源** | 交易层不产生、不修正概率；概率层未达标前，一切交易层调优无效（F-2） | F-2 优先律 |
| P2 | **方向与规模分离** | EV 只决定"买不买"，凯利只决定"买多少"；两者信号不混用 | v1 失败归因（F-3~F-5 不可归因区） |
| P3 | **只买不卖、向前对冲** | 永不市价抛售旧仓；用新资金注入实现自然对冲 | 方案 v2.8 §6、ADR-0014 持仓绝缘 |
| P4 | **本金保护绝对优先** | 遇疑即止：数据/状态不可确证时 fail-closed（撤单、禁开、静默），错失机会成本为零 | ADR-0013、ADR-0014 |
| P5 | **无风险套利独立通道** | Dutch Book 等无风险机会不占用凯利预算、不走凯利目标函数；豁免须中枢登记 | 判决书 M-3、ADR-0014 |
| P6 | **稳健优于锋利** | 在概率不确定性下按最坏情况防御（Minimax 精神），不追求峰值收益 | M-1、v1 教训 |
| P7 | **账务恒等与精度刚性** | 四桶恒等、全链路 Decimal、明确舍入口径，账不平即停机 | ADR-0012 |
| P8 | **一切实证附工件** | 任何"通过/达标"声明必须附可复现脚本、数据校验和与判定逻辑 | 项目铁律 |

## 六、既有资产 vs 新设计（框架映射）

**直接复用（已在档/已裁，规格书引用即可）**
- 概率层：EMOS 960 模型、截断、门禁（F-2 上游）
- 风控宪法：ADR-0011 两维风控、ADR-0013 熔断、ADR-0014 仲裁、ADR-0012 资金/僵尸
- 归档代码契约：ev_engine 公式、保护价/IOC 契约、risk_limiter/zombie_evaluator 契约、paper_engine 闭环

**需重新设计（本规格的增量）**
1. **稳健凯利移植改造（M-1）**：v1 Minimax 结构 → EMOS 闭式 CDF 语境（不确定集宽度来源改变）
2. **费率完整入模（M-2 修复 + 未决事项 2）**：动态费率进入 EV 与凯利，修复 fee_rate=0.0 隐患
3. **Dutch Book + 豁免的工程化（M-3）**：独立通道 + 中枢登记 + 现实深度约束
4. **两步标定落位（M-5）**：标定对象重定义（EMOS 时代）、数据源（纸面盘自产）、F-2 锁
5. **接口重建（缺失源文件）**：bankroll/execution 以 tests 契约为最低约束重建定义

**挂锁点（不可提前开工）**
- θ 标定 + sizing 调优 → F-2 概率层绿灯后解锁
- base/返佣 → 对外核实后闭环（M-2）
- 判词签署 → 用户
