## 一、 内核六条

### D-1 赚钱逻辑 `✅ 已定稿`

$$\text{edge} = \text{我们的校准分布} - \text{市场隐含概率} - \text{摩擦（价差} + \text{冲击} + \text{安全垫）}$$

- **参照系原则**：参照系是**市场价格**，不是绝对真值；不需要全局最准，只需比盘口隐含价格更准且概率校准可靠。
- **未实测声明（硬约束）**：截至 `2026-11-16`，系统盈利性尚未实测；上述三项前提假设（校准优势存在、摩擦可覆盖、盘口深度可容纳）**全部待真实盘口数据验证**，禁止提前预设收益。

### D-2 市场结构 `✅ 已定稿`

- 天气盘整体深度较低，参与者结构以散户为主（`> 70%`，*注：具体统计出处待补入档核验*）；做市商实质承担**收费流动性通道**角色而非信息型强对手盘。
- 资金容量特征为**小而稳**；仓位上限自改版运行**第一天起按盘口实时深度倒推**，不得先拍资金上限再强塞盘口。

### D-3 系统形态与历史误区澄清 `✅ 已定稿`

- **三段真实生产形态**：
  1. **GFS 翻译层**（全程生效，覆盖远期至日内先验输出）；
  2. **桥收敛层**（临近观测窗激活，依据日内实况推进条件收敛）；
  3. **结算口径适配**（目标靶 = `G-15` 结算源对齐）。
- **`max` 恒等式驱动之条件分布天然形态**：由日最高温单调极值约束 $T_{\max} \ge M_t$（$\max$ 恒等式），条件剩余分布天然呈 **“点质量（不创新高锁顶原子）+ 条件超越（突破 $M_t$ 后之正增幅连续分布）”** 双成分形态。
- **重要澄清入档（严禁误用历史指标）**：
  - **生产线自始至终消费 GFS（GEFS）预报先验**；
  - 检验 C 中使用的**气候学先验（`CRPS_native` / `Climatology` 实验隔离基线）仅是离线实验对照手段，并非系统生产真实形态**；
  - 检验 C 归档数据中的 **`−48.3%`（`−48.33%`）属于相对气候学基线对照之实验功劳簿，严禁在后续任何改版收益预期、立项论证或盈利测算中引用**。

### D-4 桥的处置与“生产即测绘”新范式 `✅ 已定稿`

- **废止前置合流测绘协议**：原拟前置验证协议彻底废止（核心事实原因：`2020–2024` 完整历史配套数据并不存在，外部回填周期与质量均为未知数）。
- **生产即测绘**：条件桥随本次架构改版直接进入生产路径，在**冻结运行期**内持续采集全量 **四元组日志**：
  1. **决策上下文**（时刻、台站、日内状态、冻结模型版本与参数快照）；
  2. **模型侧**（GFS 先验参数、桥输出分布、`p_stay` 锁顶原子、条件档位概率）；
  3. **市场侧**（实时盘口深度/价差被动记录快照）；
  4. **结算侧**（官方最终结算温度与中奖档位）。
- **新盲池定义**：**每个冻结运行周期完整沉淀的生产四元组日志，直接作为下一轮审计评估与复检的独立盲测池**。

### D-5 交易理念 `✅ 已定稿`

- **持仓周期**：以**持有至结算**为主，不主动追逐短线博弈噪点。
- **概率驱动退出规则**：**不设主观价格阈值**；当实时更新的条件概率分布与当前盘口隐含价格发生显著交叉（重算持仓继续持有期望 vs 立即卖出兑现期望并计入退出摩擦）时，由期望值对比机械触发减仓或清仓退出。
- **执行节奏**：**多次、少金额、中频扫描**（契合低深度、小而稳容量特征）。

### D-6 制度合龙 `⬜ 下一桌议程（待产出一份三段式文档）`

- **现状断点**：用户原有的“训练 → 抽检 → 亮灯（绿/黄/红）”气象评估治理体系尚未与投注交易算法合龙，存在三项明确断点：
  1. **判定对象未对齐**：红黄绿“亮灯”的判定对象尚未对齐到交易侧最小决策级；
  2. **映射缺失**：尚不存在客观统一的 **“灯 → 钱（仓位/额度系数）”映射表**；
  3. **考核孤岛**：气象模型考核制度与交易侧考核制度尚未合并为同一套管辖规程。
- **下一桌唯一交付物目标**：产出 **1 份完整合龙文档**，明确包含三段：
  1. **抽检定义**；
  2. **亮灯规则**；
  3. **灯到钱映射表**。

## 七、 `S1-06` `G-15` 裁决事实增补、`max` 恒等式定义域论证与 `T8` `M1` 规格输入（`2026-11-19` 当前决策）

> 依据 `S1-06` 补丁任务书、`S1-02 (T1 G-15)` 十站官方规则逐字取证及 [`ADR-0009 §4`](../adr/ADR-0009：芝加哥%2008-31%20特报（SPECI）结算语义裁决与截断层规则.md#4-2026-11-19-s1-06--g-15-修订节--世界事实变更跟随当前决策) / [`ADR-0012 §5`](../adr/ADR-0012：法定结算真值源（NWS%20WRH）、僵尸仓位双轨估值与舍入闭环裁决.md#5-2026-11-19-s1-06--g-15-修订节--世界事实变更跟随当前决策)（世界事实变更跟随，~`2026-10-23` 起生效），本节作为架构层就地闭环登记；所有新增口径均为 **`2026-11-19` 当前决策 / 首期选择（月度复检可替换）**。

### A｜现役结算口径三条（`G-15` 定音）

1. **数据源与三级回退链**：首选 `aviationweather.gov` 常规 **`METAR`**（8 位 `T`-group 小时温度备注 `0.1°C` 优先 $\to$ 缺失时回退报文体 `TT/TD` 整度 `°C` $\to$ 若次日 `11:59 PM ET` 前 AWC 全天无常规报则回退 **Weather Underground Daily Observations**；双方皆无则落最低档）；**`SPECI` 明确不计入结算**。
2. **时区日界窗口**：观测归属按站点 **含 DST 当地时钟自然日**（`ZoneInfo` `00:00:00–23:59:59`），`P5 tau_hours` 之 `T_settle_close_utc` 锚定为 `(target_date + 1d) 00:00:00 Local (ZoneInfo) → UTC`（不采用 Gamma `endDate=12:00Z`）；锁定点为次日首条常规 METAR 或 `11:59 PM ET` 先到者（锁前 `COR` 计数）。
3. **温度转换与正无穷半度进位**：`°F = °C × 9/5 + 32`，精确 `.5` 向 $+\infty$ 进位（官方例 `−22.5°C = −8.5°F → −8°F`，代码对应 `math.floor(x + 0.5)` / 精确半度上取整，**禁止继续沿用 `Decimal.ROUND_HALF_UP`**）；同时要求 **`M_now` 在线喂桥流与官方结算流保持完全同构**。

### B｜`max` 恒等式收窄定义域成立性论证（对应 `§一 D-3` 与 `P5` 不变量）

- **记号**：设 $\mathcal{O}_{\text{settle}}(D)$ 为目标日 $D$ 当地自然日内参与 Polymarket 结算的**全天常规 `METAR` 观测集合**（不含 `SPECI`）；$\mathcal{O}_{\text{settle}}(D, t) \subseteq \mathcal{O}_{\text{settle}}(D)$ 为截至日内扫描时刻 $t$ 已公布之常规 `METAR` 观测子集。
- **同构单调证明**：依据上方第 3 条确立的 **“`M_now` 结算同构”** 前提，在线馈入预测桥 `M2` 之极值观测量严格定义为：
  $$M_{\text{now}}^{\text{settle}}(t) = \max_{o \in \mathcal{O}_{\text{settle}}(D, t)} T_{\text{parse}}(o)$$
  由 $\mathcal{O}_{\text{settle}}(D, t) \subseteq \mathcal{O}_{\text{settle}}(D)$ 且同构解析函数 $T_{\text{parse}}(\cdot)$（`T`-group 优先 $\to$ `TT/TD` 兜底，含 `COR` 更新替换同观测时刻记录）与结算真值生成链路一致，恒有：
  $$T_{\text{settle}}(D) = \max_{o \in \mathcal{O}_{\text{settle}}(D)} T_{\text{parse}}(o) \ge M_{\text{now}}^{\text{settle}}(t)$$
  **结论**：在收窄定义域（常规 `METAR` 结算同构流）下，`max` 恒等式 $T_{\text{settle}} \ge M_{\text{now}}^{\text{settle}}(t)$、双成分“点质量（不创新高锁顶原子）+ 条件超越”形态以及 `P5` 死档硬清零不变量保持 **100% 数学成立**；反之若喂入包含 `SPECI` 的未筛选全量流，会出现 $M_{\text{now}}^{\text{all}}(t) > T_{\text{settle}}(D)$ 之反例导致错误清零获胜档位，故 **`P5` 不变量组严格限定于 `M_now` 结算同构定义域内适用**。
