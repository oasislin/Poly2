### 1.2 缺口清查：“方案有、下游无”与计划缺失切片排查

经对照《项目方案 (v2.8)》、《Phase 2 执行文件 v2.1》与代码现实，清查出以下必须重点关注的**方案有、下游无**与**计划未闭环切片**：

#### 缺口 1 · 链上争议与 UMA 仲裁退出机制（方案有概念，下游无工程状态机）
- **方案表述**：方案 §6 规定了“四桶资金状态机”中的 `Disputed Pool`，并提及 Polymarket 依赖 UMA 预言机进行争议裁决。
- **下游断裂事实**：
  1. Phase 2 执行文件及现行代码（`src/`）中，**完全缺失 UMA 争议提案监听器、争议期资金长达数日冻结与退场的工程状态机**；
  2. 若 Polymarket 盘口发生链上挑战（Dispute），系统无法在代码层面感知结算顺延或作废，资金管理模块将因超时判定为僵尸仓位，导致会计与风控双轨估值冲突。
- **归类与性质**：交易侧（执行/风控）· 缺少切片工单。

#### 缺口 2 · 实盘冷启动基础设施（生产基础设施空白）
- **方案表述**：方案 §1 规划 Phase 3 为实盘验证（零资金 $\to$ 100 USDC 最小注）。
- **下游断裂事实**：
  1. 当前代码仅支持只读 Public CLOB 端点与纸面盘模拟；
  2. **生产级基础设施完全未排期拆解**：无硬件级或 KMS 私钥保管方案、无生产 EIP-712 签名链、无带鉴权的心跳长连接（生产 WSS 订单状态回报）、无 Polymarket Proxy 合约 Allowance 授信引导流。
- **归类与性质**：交易侧（基础设施）· 方案有、下游无具体执行任务拆解。

#### 缺口 3 · 阶段转换准入门禁（从纸面盘到实盘真金的定量退出判据缺失）
- **方案表述**：执行文件设定了“W2b 纸面盘 48h 观测期”。
- **下游断裂事实**：
  1. 纸面盘 48h 观测期“通过”后，系统准入实盘真金交易的**量化门禁标准未在任何文档中被数学定义**；
  2. 缺乏诸如：48h 内最小无故障运行时间、模拟胜率、净 EV 偏差上限、最大回撤率阈值等量化门禁，目前仅有主观“无报错”定性描述，违反“判定必须下沉到代码”的最高铁律。
- **归类与性质**：风控侧（治理门禁）· 缺少指标定量规范。

#### 缺口 4 · Task 03/05/06 顺延资产的状态追踪（实盘前置依赖明晰化）
- **执行文件现实**：Phase 2 执行文件 v2.1 将原规划的 Task 03（多项联合凯利增量对冲）、Task 05（实盘执行与签名流水线）、Task 06（异常治理与 Fail-Closed 联动）顺延至“实盘前置阶段”。
- **追踪要求**：该顺延经评审委员会裁决合法有效，但必须在实盘验证启动前单独作为前置任务包进行工程立项，不得跨过 Task 03/05/06 直接跑实盘。
