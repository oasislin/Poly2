## 一、P0 级逐条挑战

### P0-1 反向 NO 套利公式 —— 结论正确，但"镜像簿恒等式"论据在 NegRisk 下不成立（专家自相矛盾）

**完全成立的部分**：
1. $\sum_i P(\text{NO}_i) = K-1$（NegRisk 互斥穷尽）✅ 数学正确；
2. 轨 B `sum(1−P̄)≥1+m` 在 K=11 恒成立 ≈10>1.02，每 Tick 误判暴利套利 ✅ 属实（已核实 v1.1 原文并废除）；
3. 两文档公式不一致（跨档求和 vs 单档配对）✅ 属实；
4. 单档配对漏算 0.05 费率 ✅ 属实；
5. 修正方案（全包 NO 对标 K−1、单档配对含费）✅ 数学正确、已采纳。

**需挑战的部分（论据错误，不成立）**：
> "同一二元市场的 YES 与 NO 共享镜像订单簿，恒有 Ask(NO_i) ≡ 1 − Bid(YES_i)，因此 Ask(YES)+Ask(NO) = 1+Spread > 1，除非盘口倒挂否则不可能触发。"

**反驳**：
- Polymarket 的 YES 与 NO 是**两个独立 token、两个独立订单簿**，撮合层**不存在强制镜像机制**；价格联动靠做市/套利维持"近似"而非"恒等"关系；
- 温度市场是 **NegRisk**：NO_i 是"其余 K−1 档 YES 组合"经转换机制发行的独立 token，其价格可**系统性偏离** 1−YES_i——偏离正是套利空间（全包 NO 轨与轨 C 都依赖这种偏离）；
- 因此"单档配对恒不触发"的结论**不成立**；恰恰是"镜像簿恒等式不成立"才让单档配对（轨 C）有触发可能。
- **专家自相矛盾**：前文用镜像恒等式论证单档配对"不可能触发"，后文修正方案又保留单档配对式 `q_eff^YES + q_eff^NO ≤ 1−m`。二者只能取其一。

**我方落位（v1.0 原文，基于当时"独立簿可偏离"认知）**：轨 A/B/C 三轨含费落位（算法描述 §9.1 / 工程落档细化 §3.5），轨 C 注明"需 NegRisk 独立 Order Book 前提"。⚠️ **该注记已随下方 2026-10-19 实证结论作废**——互补恒等为强约束，轨 C 不需要 NegRisk 前提，正确表述见实证结论第 5 条。

**实证更新（2026-10-19，用户纠正 + 真实盘口验证）**：
> 用户纠正：YES_i 与 NO_i 在**结算上互补**（温度落在档 i ⇔ YES_i=1、NO_i=0；落在其他档 ⇔ 反之），无摩擦时 Ask(YES_i)+Ask(NO_i)≈1 是**套利强约束**；因摩擦费率实际相加 **≤1 侧被 spread+费 顶住**。上轮"系统性低估 7 分"的模拟盘口**虚构了不可持续状态**，要求实时调接口验证。

**实证结论（修正上轮反驳）**：
1. **互补恒等 YES_i+NO_i=1 在真实盘口被套利锁定为精确恒等**（11/11 档 outcomePrices 全部 =1.0000，midpoint 亦然）——**用户正确，上轮"独立 token 可系统性偏离"的反驳错误**；
2. **偏离仅存在于瞬时/毫秒级**（套利机器人立即拉平），"系统性低估 7 分"是虚构的不可持续状态；
3. 轨 C 单档配对在**正常盘口几乎不触发**：YES spread=0.025（0.948~0.973）可见，裸价 Ask(YES)+Ask(NO) ≥ 1+spread > 1，含费后更 > 1——**专家"几乎不触发"的结论正确**（其"镜像簿强制"论据表述仍不准确，但结论方向对）；
4. **三轨全部废除（2026-10-19 v3 定论）**：轨 A（全包 YES）——公理性不可能（Σp=1，盘口总和被套利均衡钉在 ≥1+摩擦，实测 ΣAsk(YES)=1.0170）；轨 B（全包 NO）——镜像冗余（互补恒等 ΣAsk(YES)+ΣAsk(NO)≡K 下，"ΣNO≤K−1−m"⟺"ΣYES≥1+m"）；轨 C（单档配对）——机制性恒等（split/merge 固定 $1/对，1 YES+1 NO≡1 pUSD）。**死代码有害论**：永不触发的判定逻辑只承担误触发 bug 风险（轨 B 错误不等式即实例：公式一错即每 Tick 误判下单）、不产生收益——三轨全部移除。**S6 裁定（项目方，2026-10-19）：保留只读错价监控**——观测单档互补偏离与跨档总和偏离、低频轮询、超阈值告警日志，**不触发任何下单**，纯观测供人工/审计消费（规格见《致外部顾问对齐回复 v3》§一.4）；
5. **对文档影响（三轨移除 + S6 降级）**：①算法描述 §9.1 / 工程落档细化 §3.5 移除轨 A/B/C 全部判定式，"套利前置最高优先级"（Q2 裁决）作废并新增 DR 留痕；②轨 C 现存注记"需 NegRisk 独立 Order Book 前提/定价脱节前提"随轨 C 一并删除（无需替换）；③m_dutch 参数挂锁失效，标"废弃"；④P1-4 max_rehedge_loss/ResidualHealer 补单逻辑仅与套利通道耦合，一并降级/移除；⑤全档深度前置检查（原防缺腿建议）随三轨废除取消。

### P0-2 LP 强对偶展开 —— 工程方向正确，但 3 处数学表述不严谨

**完全成立的部分**：内层 LP 极点切换非光滑；argsort 翻转→有限差分梯度跳变→SLSQP 线搜索失败风险；G7 Fail-Closed 全零="安全但假死"；LP 强对偶展开数学正确（我已独立验算弱对偶 + 数值强对偶）。✅

**需挑战的部分（表述瑕疵，不影响工程方向）**：
1. "目标函数 g(f) 确实是**严格凹函数**"——不严谨：$\ln W_i$ 是仿射函数的对数，凹；正加权和保凹，但**未必严格凹**（若某档 $\hat p_i=0$ 或存在线性方向）。凹性保证全局最优，**严格凹才保证唯一解**；
2. "SLSQP 保证收敛至 KKT 点，即**全局唯一最优解**"——过强：凹最大化于凸集保证全局最优，但 (a) 线性目标在凸多面体上最优解**可能非唯一**；(b) SLSQP 数值实现**不保证 100% 成功**（浮点、缩放、退化），所以**保留 Fail-Closed 兜底是必须的**——它是与对偶化互补的工程层，不是冗余；
3. "高频假死"的严重性为**推断**（专家未实测频率）——合理担忧，采纳对偶化从根源消除，无论频率高低都值得。

**我方落位**：单层对偶（3K+1 变量、闭式 Jacobian、Slater 初始点）+ **Fail-Closed 原样保留** ✅（互补两层，正确）。

### P0-3 下单漏费/截断/eps —— 完全成立，无挑战点
三处均属实并已修复：含费折算 `min(f*/q_eff(P_protect), safe_capacity)`、含费足额预冻结 `lock_funds(S×q_eff)`、eps 签名 4 处补齐。✅

### P1-2 τ 前置化 —— 成立，但专家修正公式与 P1-3 自相矛盾（重点）

**完全成立的部分**：后置乘法 ≠ 前置预算（非线性目标下不可交换）✅；小额订单被 minimum_order_size 团灭场景 ✅；evaluate_all_gates 缺 G3/G4 ✅。

**需挑战的部分（专家报告内部矛盾，我方未照单全收）**：
> P1-2 修正公式写：$C_{\max} := \tau_z \cdot \tau_{\text{2D}} \cdot \min(0.10 \cdot B_{\text{eff}},\; \mathbf{0.70 \cdot \text{Total}} - \text{Active\_locked},\; W_{\text{free}})$

- 该公式第二项用 **Total**（含 Zombie/Disputed）分母；
- 而专家在 **P1-3** 中恰恰批评 Total 分母"把冻结僵尸当安全垫放大活跃敞口、违背 M5 审慎原则"，建议统一 B_eff；
- **同一份报告内，P1-2 用 Total、P1-3 反对 Total——直接矛盾**。

**我方处理**：裁决统一 B_eff（DR-2026-1014-03），落位为 $C_{\max} = \tau_z\cdot\tau_{\text{2D}}\cdot\min(0.10 B_{\text{eff}},\; 0.70 B_{\text{eff}}-\text{Active\_locked},\; W_{\text{free}})$——即采纳了专家 P1-3 的审慎原则，拒绝 P1-2 公式中的 Total 口径。ADR-0012 已版本标注联动（分子分母双向剔除 Zombie）。✅

### P1-3 G2 分母 —— 完全成立，无挑战点
三处不一致属实；Total 分母放松约束的分析正确；统一 B_eff 已落位（算法描述 §7 / 工程落档细化 §5 / ADR-0012 联动）。✅

### P1-4 缺腿死锁 —— 成立，但补单阈值口径不完整（新增 1 项落实细节）

**完全成立的部分**：并发 FAK 缺腿 + 禁 SELL 死锁真实；max_rehedge_loss 方案合理（已落位 0.02 [待标定]）。

**需挑战的部分（表述不完整）**：
> "若补单价格使得全包总成本 $\sum q_{\text{eff}} \le 1 + \text{max\_rehedge\_loss}$，允许贴水补单"

- 该式只对标**全包 YES 轨**的保底赔付 1；
- **全包 NO 轨的保底赔付是 K−1**，补单阈值应对标 $(K-1) + \text{max\_rehedge\_loss}$；
- 我方文档现写"rehedge_loss ≤ m_rehedge"未按轨区分——**实现细节需落实**：ResidualHealer 按套利轨对应保底值比较（YES 轨对标 1、NO 轨对标 K−1）。

**新增落实项**：建议开发端在 ResidualHealer 实现时按轨区分补单阈值对标（文档层面可加一句注明）。
