## 四、请开发端逐节挑战审阅的维度

1. **流程拓扑**：S1→S6→S2→S3→S4→S5→S7 + 横切 M-G 的顺序与数据流；S6 前置的合理性；决策快照冻结原则（N3）的实现可行性；
2. **模块职责与接口**：M1~M8 + M-G 的职责划分、输入输出、接口签名方向（尤其 M2 凯利、M4 执行——bankroll/execution 无旧代码可依，接口由本规格书定义，请从工程可行性挑战）；
3. **数学正确性**：算法文档 §2~§11 全部公式——重点：§3 凹性证明（引理 1~3）、§4 Delta Method 灵敏度（高斯族闭式；JSU/EVT-Hybrid 标注公式族待推导）、§5 贪心投影精确性（box+simplex 线性规划极点解）、§9 套利判定式（Taker/Maker 双式）；
4. **门禁不等式与判定下沉**：§7 G1~G7 的完备性（有无遗漏门禁）、布尔下沉可测性；
5. **工程可行性**：SLSQP 求解规模与耗时、深度穿透与费率时序、IOC 路由、残差愈合状态机、四桶账务 Decimal；
6. **挂锁纪律**：参数挂锁表有无遗漏（任何影响 sizing/标定的数字都必须锁定或标注来源）。
