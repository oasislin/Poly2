## 2. 单轮闭环（每轮必须走完）

1. 审核方出任务书/裁决 → 开发端执行（只在授权范围）。
2. 开发端回交：脚本路径、原始结果表、复现命令、退出码、输出末尾原始片段、数据校验和。
3. 审核方机械复算判定（原始值 vs 阈值，不主观调和），写结论。
4. **更新对应文档**（任务书结果小节、封盘清单、本登记档），再 commit。
5. 原始观测值不可篡改；未执行的测试不得写「通过」。

## 3. 文档更新规则（每次调整必更新对应文档）

- 检测类：更新任务书「执行结果」小节，附原始表路径与校验和。
- 封盘类：更新《V1_2019盲测_封盘清单》SHA-256 与 commit hash。
- 台账：本轮结束后把条目摘要与 commit hash 补登 `docs/audit/DECISION_LEDGER.md`（开发端落盘）。
