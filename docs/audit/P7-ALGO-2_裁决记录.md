## DR-2026-1014-01：S1 定价探针规模 S_target 取值规则（外部审计 P1-1）

**纠结点**：S1 需按目标规模穿透 Asks 计算 P̄ 与 q_eff，但 S2 凯利尚未运行、未知每档分配——"鸡生蛋"循环。传错规模会误杀正 EV 小单或高估成本。

**候选方案**：
- A（专家建议）：`max(minimum_order_size, min(safe_capacity_at_min_edge, 单档合理探针规模))`——独立探针参数；
- **B（裁决选择）**：S_target 不由独立参数定义，而由 min_edge 达标穿透自动确定——`S_target := Σ_{j: edge_j ≥ min_edge} s_j = safe_capacity_at_min_edge`；定价 P̄ = 达标深度加权均价；q_eff 冻结于此时序；
- C：按单市场上限 0.10·B_eff 全预算穿透。

**裁决理由**：
1. 消除鸡生蛋——定价基准不再依赖 S2 输出；
2. 保守且自洽——达标深度内任意分配规模，实际成交均价 ≤ P̄、成本 ≤ 快照 q_eff；S4 截断至 safe_capacity（P0-3 修正）保证执行不超出定价假设深度；
3. 与 §4.4 `calculate_protection_price` 复用同一穿透逻辑，**不新增独立参数**，杜绝两处口径漂移；
4. 误杀方向（达标深度浅时漏边缘小单）为保守次优，可接受；虚报方向由 S4 截断自洽兜底。

**未选及原因**：A 引入新参数且与 §4.4 形成双重穿透（两处易漂移）；C 高估成本系统性误杀小单。

**代价/剩余风险**：达标深度很浅时 P̄ 偏高→edge 低估→漏单；防御=S4 `minimum_order_size` 门禁兜底（漏单≠错单，安全方向）。

**联动修订**：算法描述 §2.1 公式化 S_target 定义；工程落档细化 `evaluate_pricing` 签名注释来源。

## DR-2026-1014-02：风控折剪 τ_z/τ_2D 前置化（外部审计 P1-2）

**纠结点**：规格书冻结条款"宪法硬顶与调制全在 S3 实施"——S2 全额求解 f* 后 S3 后置乘 τ。凹目标下"先求 f* 再乘 τ" ≠ "预算先缩 τ 再求 f*"；后置导致小额订单被 minimum_order_size 团灭（每档 8→1.6 pUSD→全 <5 shares 全军覆没）。

**候选方案**：
- **A（裁决选择）**：τ 前置并入 S2 预算上限——`C_max := τ_z · τ_2D · min(0.10·B_eff, 0.70·B_eff − Active_locked, W_free)`；S3 转为纯布尔放行；
- B：保持后置，接受团灭风险。

**裁决理由**：
1. 数学正确性：凹优化下预算缩放是正确操作，后置乘法破坏最优性；
2. 前置后 SLSQP 自动集中预算到 edge 最大档位，跨过 minimum_order_size 门槛；
3. 时序可行：τ 依赖的观测（T_rem/ΔT/R_z）在决策快照 N3 内已冻结，前置无时序障碍；
4. **折剪点唯一化原则保留**：调制并入 S2 预算公式（唯一位置），S3 仅布尔放行（G3/G4 = τ>0 有效性检查）——不产生多重折剪叠加。

**未选及原因**：B 数学次优 + 团灭实盘风险。

**代价/剩余风险**：τ 语义从"事后调制"变"预算调制"，审计口径变化（x_approved 反映 τ 后预算）；由决策快照记录覆盖。

**联动修订**：规格书 L72 改写（"调制并入 S2 预算上限公式唯一化；S3 门禁布尔放行，无乘法调制"）；算法描述 §3.2 C_max 公式；工程落档细化 §5 evaluate_all_gates 补 G3/G4 布尔；§3.3 管线图标注。

## DR-2026-1014-03：G2 全局利用率分母口径（外部审计 P1-3）

**纠结点**：算法描述 §3.2 用 `0.70·B_eff`，§7 G2 表与工程落档细化用 `Total`（含 Zombie/Disputed）分母——三处不一致；且 ADR-0012 原文定 Total 分母（"Zombie/Disputed 从分子剔除"），矛盾在 ADR 与规格书 M5（Zombie 0.0x）之间。

**候选方案**：
- **A（裁决选择）**：统一 `B_eff`（Free + Active）；Zombie/Disputed 分子分母**全剔除**；
- B：统一 Total（沿用 ADR-0012 字面）。

**裁决理由**：
1. 风险语义：利用率 = 活跃敞口 / **可运作资金**；Zombie/Disputed 冻结不可动用，放分母相当于"借冻结资金放大杠杆"，与审慎原则冲突；
2. 保守方向：B_eff ≤ Total → 分母更紧 → 活跃敞口上限更低（宁可紧不可松）；
3. 一致性：C_max 已用 B_eff（§3.2），统一后 §3.2 / §7 / 落档细化 §5 三处一致；`0.70·B_eff − Active ≥ Σf ⟺ (Active+Σf)/B_eff ≤ 0.70` 数学等价；
4. 规格书 M5"Zombie 0.0x 剔除"精神贯彻到底。

**未选及原因**：B 与审慎原则冲突、且与 C_max 的 B_eff 口径不一致。

**代价/剩余风险**：Zombie 占比高的场景活跃敞口上限更紧（保守代价，可接受）；B_eff 定义需文档明确（Free+Active）。

**联动修订**：**ADR-0012 需版本标注修订**（"利用率分母统一 B_eff，Zombie/Disputed 分子分母全剔除"，按项目规则 ADR 走版本标注不重写）；算法描述 §7 G2 表；工程落档细化 §5 G2 代码。

## DR-2026-1014-04：G4 温标处理方案（外部审计 P2-1）

**纠结点**：规格书 §1 硬编码"2°F 档位"、G4 硬编码 `ΔT>3°F / ≤0.5°F`；国际站同时含 °F（US 站）与 °C（ZSPD/UUWW/LLBG）站点，套用放大 1.8 倍。

**候选方案**：
- A：MarketMeta 增 `temperature_unit` 字段 + F/C 硬换算（3°F↔1.67°C、0.5°F↔0.28°C）；
- **B（裁决选择，主）**：G4 阈值改用**标准化残差** `z = |ΔT| / σ_EMOS`（无量纲）；`temperature_unit` 字段**仍必加**（结算复刻/决策上下文需要）；°F 原始阈值保留为参考换算基线；
- C：DecisionContext 内部统一转华氏（仍需温标信息，故字段不可省）。

**裁决理由**：
1. 无量纲彻底规避温标问题（无需 F/C 判断分支，消除硬编码冲突根源）；
2. 语义更准：G4 CRITICAL 的本质是"模型置信度低 + 临近结算"，σ 归一化正是该语义；绝对阈值在 σ 小的站点过严、σ 大的站点过松（绝对阈值固有缺陷）；
3. 适配每站每时刻 σ 变化，与 EMOS 输出天然衔接；
4. `temperature_unit` 为必要字段，无论主方案为何都必须加（与 P2-3 的 `station_tz` 一并落位）。

**未选及原因**：A 单独方案引入两套阈值分支且保留绝对阈值缺陷；C 仍依赖字段，且转换层冗余。

**代价/剩余风险**：z 阈值（z_crit/z_cert）为**新增标定项 [待标定]**（F-2 绿灯后经标定流程定稿）；与 ADR-0011 原始 3°F 的对应关系需标定校准（参考：σ≈1.5°F 时 3°F ≈ z≈2.0，仅参考值非定稿）。

**联动修订**：算法描述 §7 G4 表改写（z 阈值 + °F 换算基线注）；工程落档细化 MarketMeta 增 `temperature_unit`/`station_tz`；规格书 §1 档位表述标注"按站点温标（F/C）"。
