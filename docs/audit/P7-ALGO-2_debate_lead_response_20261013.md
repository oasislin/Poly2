## 一、6 项议题逐项立场

### 议题 1：凯利不确定集构造 ——【采纳工程约束 + 升级为混合双源】

开发端方案（独立边界 + η 膨胀 + 冻结区间）的工程理由成立：区间耦合会摧毁贪心投影的 $O(K\log K)$ 单调性保证。**采纳**。

**主导方升级**：SE_i 采用**双源取 max**（对齐 v1 卷宗 4.1 结构 `std_errors_adjusted = max(std_errors_normalized, se_model)`）：

$$\text{SE}_i = \max\left(\text{SE}_{\text{EMOS}, i},\; \eta\sqrt{\hat{p}_i(1-\hat{p}_i)}\right)$$

其中 $\text{SE}_{\text{EMOS}, i}$ 由 EMOS 闭式 CDF 对档位 $[a_i, b_i]$ 的**参数灵敏度（Delta Method）解析派生**（高斯族闭式：$\partial p_i/\partial \mu = \left(\varphi(z_{a_i}) - \varphi(z_{b_i})\right)/\sigma$，$\partial p_i/\partial \sigma$ 同理；JSU / EVT-Hybrid 同法可解析）：

$$\text{SE}_{\text{EMOS}, i} = \left|\frac{\partial p_i}{\partial \mu}\right|\delta_\mu + \left|\frac{\partial p_i}{\partial \sigma}\right|\delta_\sigma$$

- **正面回应判决书 M-1 拷问 4**："EMOS 的分布参数能否直接给出区间宽度？→ 能（Delta Method 闭式），替代 v1 经验 std_errors"——这是 M-1"改造移植"的核心增量，纯 η 膨胀方案未兑现该判词；
- **收敛性保全**：区间边界在**决策快照内冻结**（一次快照算好 $p_{L,i}, p_{U,i}$，不进 SLSQP 迭代重算）→ 贪心投影每次迭代 $O(K\log K)$ 不变；
- **挂锁**：$\delta_\mu, \delta_\sigma$ 尺度 + $\theta, \eta$ 全部 `[F-2 LOCKED]`，初值不猜。

### 议题 2：Dutch Book 与凯利共存 ——【采纳 + 3 条补充】

采纳开发端方案：S6 前置 S2、最高优先级、豁免 $C_{\text{loc}}$（10% 单市场）、上限 $\min(\text{Free}, C_{\text{total}}-\text{Active})$、中枢登记、剩余资金回流凯利。

**主导方补充 3 条**：
1. **70% 全局利用率不豁免**：套利占用计入 Active Locked，账户级流动性安全线（70%）是宪法级，v1 仅豁免 $C_{\text{loc}}$（卷宗 4.3 原文），规格书延续此口径；
2. **现实可成交性约束**：套利机会实际上限 = 盘口可成交深度（判决书 M-3 拷问 3 的现实约束：$300\sim2500$/档），理论无风险但不可成交的扫描必须剔除；Taker 与 Maker 两套判定式分别落位（v1 WEP §6.1 两式均含费率项），Maker 挂单套利优先（返佣支持）；
3. **margin_dutch 参数处置**：v1 现值 2% 按 M-8 原则**不直接继承**，规格书登记为"宪法推导或两步标定复核"项，暂以现值占位、标注 `[待复核]`——判词签署待用户。

### 议题 3：带旗资产进凯利 ——【采纳分级折剪 + 折剪点唯一化（关键修正）】

采纳分级：Paper 0.5x 折剪 / Live 一票否决 / FAILSAFE 只读。

**关键修正（主导方）**：**折剪点必须唯一化，禁止双重折剪**。现役 `ev_engine.py` 已在定价信号层实施 `is_flagged → target_size×0.5`（在档代码事实），若 S3 闸门再对凯利输出折剪，会误伤为 0.25x。规格书必须明确：**带旗折剪仅在 S1 定价层实施一次**（对齐现役代码），S3 只施加宪法硬顶（10%/70%/僵尸分级），不重复折剪。此为接口级必敲项，开发端落档时须统一。

### 议题 4：两步标定 ——【采纳 + 重定义为"门禁审计 + 反事实 sizing"】

采纳开发端核心：交易层不重标气象参数（P1）、第二步反事实 sizing 模拟（θ,η）、时序分割（70/30）、`[F-2 LOCKED]`。

**主导方精确化**：v2 语境两步标定重定义为——
- **Step 0（概率质量审计，非标定）**：消费概率层门禁报告（ADR-0018 Binding + 交易窗口 ECE）作为 F-2 绿灯证据；交易层不产生、不修正概率（P1 的工程化）；
- **Step 1（金融 sizing 反事实模拟）**：纸面盘自产订单簿/成交/结算时序 + prob_cache 两阶段网格架构复用（标定方案 §3），目标 = 几何增长率 / 夏普最优的 $(\theta, \eta)$；
- **先验纪律**：v1 历史样本**不作为 θ/η 先验**（防 F-2 污染转移，M-5 拷问 1 的裁决倾向：纸面盘数据自产达标前挂锁）；
- Platt Scaling / 保序回归（开发端提及）：属概率层离散映射职责（F-2 上游），本规格只登记接口，不越权定义。

### 议题 5：缺失源文件重建 ——【修正事实 + 采纳契约驱动】

**事实修正（重要）**：开发端称"以现有归档源码（src/bankroll/、src/execution/ 等 **27 个已存文件**）为基础骨架"——**该前提不成立**。经磁盘实测：归档区 `src/` 实际在档 **16 个源文件**（risk 6 + pricing 2 + simulation 8）；`src/bankroll/` 与 `src/execution/` 目录**为空，11 个源文件物理缺失**（全项目无副本、本机无 git）。详见 `P7-ALGO-2_素材盘点.md` §4.1。

**修正后方案**：
- bankroll/execution（11 缺失）：以 **8 个 tests 行为契约 + paper_engine/execution_engine 调用关系 + 判决书/卷宗 v1 摘录** 为骨架反推接口；tests 为最低验收契约（100% 绿回弹）；
- risk/pricing/simulation（16 在档）：以在档源码为骨架直接重构；
- 恢复路径：若用户可从真实 git 仓库恢复 11 个源文件补入归档区，可降级反推风险——但**规格书设计必须独立于源文件成立**（tests 契约已足以定义接口语义）；
- 修复点认可：DynamicFeeModel 入 ev_engine（修复 fee=0 隐患）、Minimax 入 multinomial_kelly（M-1 移植）。

## 二、两项工程约束确认

1. **VWAP→费率时序**：【采纳】。对齐 v1 已裁公式 `q = \bar P\cdot[1 + \text{base}(1-\bar P)]`（卷宗 4.2，strategy.py:691）；补充：VWAP 穿透按目标规模分档累计（对齐 ev_engine `calculate_effective_price`）；$\bar P \to 0$ 边缘档绝对费用小但费率摩擦高，EV 判定须保留 edge 的费率敏感性（不得因绝对费用小忽略）。
2. **SLSQP Fail-Closed**：【采纳】。对齐 tests 契约（`test_optimizer_fallback_on_invalid_inputs`：维度不匹配/负 w_free → success=False + 全零）；补充两条：
   - NaN/脏解防御覆盖**输入**（p̂ 含 NaN/越界）与**输出**（x* 含 NaN）两个方向；
   - **连续 N 次求解失败 → 联动 ADR-0014 上报**（台站降级/人工介入），不止静默归零——静默归零与"遇疑即止"不冲突，但必须留痕。
