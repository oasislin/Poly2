# ADR-0008：GEFS 再预报全池采购、源文件冷归档与时区自适应（GEFS-WI-v1.1 综合裁决）

- **状态**：Accepted
- **日期**：2026-09-07
- **裁决人**：项目负责人
- **影响范围**：GEFS 再预报获取管线、存储策略、特征因子提取（Task C）与离线特征库构建

## 1. 背景

在推进 Phase 1.5 重建 12 站校准语料与 GEFS 特征库过程中，对历史 GEFS 再预报资产与下载机制进行实测与代码复核，确认以下硬事实：

1. **全球场物理事实**：存量 GEFS subset 文件为 **全球 0.25° 格点场**，按报文（变量 / lead 段 / 成员）切分。文件名中的城市仅为当年检索请求条件，与内容空间范围无关。不存在"按站下载"，任何站点的数据均在同一份全局场文件中；
2. **存量时效断层**：存量 lead 仅覆盖 {24, 30, 36}h 与 {42, 48, 54}h 两段。因历史下载脚本（`gefs_batch_downloader.py` 第 264 行）硬编码 `target_date = init_day + timedelta(days=1)`，导致 Day 0 目标日从未被调度，短 lead 段（0–21h）从未进入下载计划；
3. **时区投影差异**：既有 {6h, 30h, 54h} / {24h, 48h} 体系系东八区（UTC+8）本地日投影；美洲站点的本地日窗口整体右移（如芝加哥 CDT=UTC-5 投影为 TMAX {24, 48, 72}h / TMIN {12, 36}h），硬编码单一时区节点导致美洲站数据缺失；
4. **外部存储就绪**：原始数据根目录已迁移至外部移动固态存储（`/Volumes/EricSSD/Poly RawData/gefs_reforecast/`）。

## 2. 决定

| # | 裁决 | 内容 |
|---|---|---|
| **D1** | **一起下载（全池并集采购）** | 补抓范围按 12 站全池的 fxx 并集执行，一次性下载覆盖全池，严禁为单站省量或分站割裂下载 |
| **D2** | **原始文件保留（冷归档）** | 提取后原始 GRIB 完整保留，冷归档于外部存储；严禁在提取或清洗过程中删除任何源文件（删除属数据销毁决策，须另立 ADR） |
| **D3** | **提取程序参数化** | 开发路径参数化的独立提取程序 `src/pipeline/gefs_extract.py`，支持指定外部输入目录、输出目录、站点列表、年份范围与 `--dry-run` |
| **D4** | **节点时区自适应** | lead 节点数值由 `select_contained_6h_windows` 按站按时区动态计算，严禁对任何站点硬编码 {6, 30, 54} 等静态节点 |

## 3. 否决的备选方案

- **按站单独下载或单站定制 fxx**：被否——GEFS subset 物理上是全球格点场，按站重复请求不仅徒增 12 倍网络带宽开销，且显著增加 AWS/NOAA 封禁风险；
- **提取后就地删除原始 GRIB 节约磁盘**：被否——GRIB 原始场为权威不可再生底座资产，删除将彻底破坏后续审计与未来扩展更多气象变量（如风速、降水）的可能性；
- **人工手工推算各时区固定节点**：被否——夏令时（DST）动态切换会导致本地日对应的 UTC 窗口偏移 1 小时，静态手工推算无法防御 DST 边界，是历史 Bug 的根源。

## 4. 后果

**正面**：
- 确立以程序化探针（Task A）输出的并集清单作为唯一采购标准，杜绝重复采购与漏抓；
- 确立冷归档数据资产安全红线（源文件零删改）；
- 提取逻辑与存储路径解耦，支持任意环境指定外部存储路径运行。

**负面 / 代价**：
- 全池 fxx 并集扩展使得总下载数据量增加（新增短段与长段）；
- 需要依赖外部固态硬盘 `/Volumes/EricSSD/` 进行大数据吞吐与冷归档。
