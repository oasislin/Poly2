# ADR-0011：双源单调合流架构、TMAX-TMIN 对称截断与两维阶梯风控裁决

- **状态**：Accepted
- **日期**：2026-09-19
- **裁决人**：量化工程团队
- **影响范围**：Phase 2 执行文件 v1.3（§5.2）、动态截断层（`dynamic_corrector.py`）、风控与陈旧监测系统（`alert_manager.py`）、系统配置规范（`default.yaml`）

---

## 1. 背景与冲突下钻 (Context & Problem Analysis)

### 1.1 历史条款与数据源重铸后的矛盾
在《Phase 2 执行文件 v1.3》§5.2 中，原系统针对动态截断层与数据源监控设定了以下规则：
1. **源切换设计**：在名义极值时刻前 2.0h 进入“口径切换窗口”，截断层输入由常规 METAR 切换至实况页（原方案为 Wunderground），旨在消除结算口径差；
2. **陈旧阈值跳变**：切换窗口内的陈旧超时阈值由常规时段的 3.0h 骤降为 0.75h（45 分钟）；
3. **降级惩罚动作**：一旦超时触发 `DATA_STALENESS`（ERROR 级），系统执行“截断层自动下线、Effective $\sigma$ 放大 1.3 倍、EV 阈值由 0.03 提至 0.05”。

随着前序架构裁决与 Phase 1.5 证据产出，上述设计暴露出三大根本性矛盾：
- **矛盾一（ADR-0007 / ADR-0009 事实）**：Wunderground 已被彻底废除，法定结算源确立为 NWS WRH 时序表，而校准与高频监控主力源确立为 IEM ASOS 原报（RMK T 组 0.1°C 精度）。两者底层均源自同一物理 ASOS 台站传感器，实测日极值偏差 $|\Delta T| \le 0.48^\circ\text{F}$（源自 WRH 前端展示四舍五入舍入伪影）。在临近极值决战期强行将主驱动切向网络跳数更多、依赖第三方 API 渲染的 WRH，构成**拓扑逻辑倒挂**；
- **矛盾二（量纲与风控真空）**：Active 交易站均为日发报 $\ge 310$ 报（5 分钟一报）的高频站点。0.75h（45 分钟）相当于容忍连续丢失 8~9 报，占整个 2h 窗口的 37.5%，在此盲盒期内极易遭受盘口逆向选择；而若机械收紧至 20 分钟，又会被 ASOS 固有物理传输延迟（P50 约 18~20 分钟）频繁触发假阳性；
- **矛盾三（降级动作自毁防线）**：极值具有物理不可逆性。在数据断流失明期将截断层下线并放大 $\sigma$，会导致已被实测淘汰的死档重新获得虚高模型概率，诱发向死档下注的致命操作风险。

### 1.2 交易站点宇宙范围收敛
依据用户明确裁决与六要素受控元数据审计：
- **交易站宇宙**：严格锁定于 **Active 10 高频交易站**（`KORD`, `KLGA`, `KATL`, `KDAL`, `KSEA`, `KLAX`, `KHOU`, `KMIA`, `KSFO`, `KAUS`），日发报数均在 310~317 报，具备均一的高频观测特征；
- **排除站界定**：低频特例站 `KBKF`（日发报 25 报，`ADMITTED_TIER_3_WARNING`）不纳入 Phase 2 主力交易；`KDCA` 彻底下线退役，严禁引入。

## 2. 裁决决定 (Decisions)

### D1：废除主从硬切，确立“双源单调合流架构（Dual-Active Monotonic Driver）”
1. **拓扑职责分工**：
   - **IEM ASOS 实时原报流**：作为**全天候主力物理驱动源（Primary Physical Ingestion Driver）**，以 0.1°C RMK T 组精度接收分钟级报文（包含 Routine METAR 与 SPECI 特报），保证最低物理传输延迟；
   - **NWS WRH 官方时序表**：作为**异步影子对齐源（Asynchronous Shadow Settlement Observer）**，定期轮询抓取，用于对齐 Polymarket 官方结算可能存在的舍入显示特征；
2. **单调合流驱动法则**：
   - 彻底废除“名义极值前 2h 跨源切换”的状态机时钟。全天候采用统一的单调极值驱动算子，任何一源合法上报更高（针对 TMAX）或更低（针对 TMIN）的有效物理观测，立即单向收紧截断门禁：
     $$\text{TMAX: } T_{\text{max\_so\_far}} = \max\left(T_{\text{IEM\_max}}, T_{\text{WRH\_max}}\right)$$
     $$\text{TMIN: } T_{\text{min\_so\_far}} = \min\left(T_{\text{IEM\_min}}, T_{\text{WRH\_min}}\right)$$
   - 架构上彻底根绝跨源切换引发的网络抖动、状态机震荡与延迟放大。

### D2：TMAX 与 TMIN 预测与截断模型的完全平权对称架构
严格遵循项目方案 v2.6 §9 规则 4，确立最高温与最低温模型在数学、时序与工程上的全平权对称：

| 架构要素 | 最高温模型（TMAX） | 最低温模型（TMIN） |
| :--- | :--- | :--- |
| **物理极值特征** | 日内最高温（Peak / Maximum） | 日内最低温（Trough / Minimum） |
| **典型时段分布** | 午后至傍晚（当地 14:00 ~ 17:00） | 黎明及日出前后（当地 04:00 ~ 07:00） |
| **截断层数学约束** | **下界不可逆锁死（Lower Bound Clamping）**：<br>$\mathbb{P}(T < T_{\text{max\_so\_far}}) \equiv 0$ | **上界不可逆封顶（Upper Bound Clamping）**：<br>$\mathbb{P}(T > T_{\text{min\_so\_far}}) \equiv 0$ |
| **物理突变早锁判定** | 实测遭遇断崖降温（如对流雷暴连续 3 报跌 $\ge 3.0^\circ\text{F}$ 伴随降水）且过正午，峰值提前锁定 | 实测遭遇破晓升温（日出后连续 3 报回升 $\ge 3.0^\circ\text{F}$ 伴随强日照），谷值提前锁定 |
| **历史持续性辅助** | 结合当日 GEFS/HRRR 曲线峰值时刻与近 3 日实测峰值均值 $\bar{t}_{\text{recent\_max}}$ 综合推算高危期 | 结合当日 GEFS/HRRR 曲线谷值时刻与近 3 日实测谷值均值 $\bar{t}_{\text{recent\_min}}$ 综合推算高危期 |

### D3：两维阶梯风控防线与未成交挂单撤销铁律 (CancelAll Protocol)
废除脱离实际发报节奏的单一 45 分钟硬编码，建立“**到达心跳**”与“**物理龄期**”两维防御体系：

1. **第一道防线：到达心跳超时（Feed Arrival Lag）—— 15 分钟**
   - **判定条件**：系统距离上一次成功接收到该台站任意源新报文的时间间隔超过 **15 分钟**（即连续丢失 3 个 5 分钟发报周期）；
   - **触发级别**：`WARNING` 级告警；
   - **执行动作（CancelAll Quotes）**：
     - **概念严格界定**：已成交持仓（Positions / Filled Bets）在链上与撮合规则上物理不可撤销，保持持有至结算；
     - **撤单铁律**：执行引擎必须毫秒级向 Polymarket CLOB 发送 `cancel_all()` 指令，**撤销当前挂在订单簿上所有排队等待撮合的未成交限价挂单（Maker Quotes）**，并坚决禁止发送任何新开仓订单；
     - **防御目标**：死封既有风险敞口，彻底消除在数据断流期间被场内知情交易者（Informed Traders）按过时报价逆向选择打劫的风险。

2. **第二道防线：绝对物理龄期超限（Observation Staleness）—— 35 分钟**
   - **判定条件**：当前有效观测数据报文内部记录的 UTC 时间戳 $t_{\text{obs\_utc}}$ 距当前真实时间超过 **35 分钟**（覆盖 ASOS NOAA P50 18~20m 延迟 + 网络轻度抖动 P95 宽限）；
   - **触发级别**：`DATA_STALENESS`（ERROR 级）；
   - **执行动作（Hard Circuit Breaker）**：
     - 触发系统级交易熔断，进入 `SAFE_MODE`；
     - 拒绝接收任何新的 `OrderIntent`。

### D4：截断层约束单向永久锁定法则
- **严禁截断层下线**：彻底废除 Phase 2 v1.3 中“数据陈旧后截断层自动下线停用”的致命错误逻辑；
- **单向锁定不可逆性**：截断层所维护的 $T_{\text{max\_so\_far}}$（下界）与 $T_{\text{min\_so\_far}}$（上界）属于物理世界已确证发生的事实。无论外部数据链路发生何种断流、降级或熔断，**已生效的截断概率归零约束永久有效，绝不下线、绝不清空**；
- 严禁在失明期通过放大 $\sigma$ 伪造尾部概率向死档下注。

### D5：时间戳单调守恒与抗震荡（Flapping）迟滞回线
1. **时间戳单调守恒**：
   - 系统所有时延与龄期判定一律以报文解析出的 **UTC 物理观测时间戳（`timestamp_utc`）** 为唯一基准；
   - 丢弃任何物理时间戳早于当前已入库最大时间戳的网络乱序帧/迟到帧，严禁迟到帧重置风控看门狗；
2. **迟滞恢复（Hysteresis Recovery）**：
   - 处于熔断降级或撤单保护状态的站点，必须满足以下条件方可解除：
     ① 接收到新报文且物理龄期回落至 20 分钟以内；
     ② **维持连续 3 帧（至少 15 分钟）持续健康发报**；
   - 彻底杜绝阈值边缘网络抖动引发的频繁切入切出与高频挂撤单震荡。

## 3. 后果与架构收益 (Consequences)

### 3.1 正面收益
1. **架构复杂度降维**：去除了脆弱的名义极值倒计时切源状态机，以单一数学算子 $\max / \min$ 统领全天候极值截断，代码实现清晰且高内聚；
2. **消灭交易逆向选择风险**：15 分钟丢心跳即撤销排队未成交挂单，确保系统在盲盒期零暴露；
3. **消除模型倒退致命伤**：确立截断约束永久锁定法则，杜绝了断流期重新向被淘汰档位错误下注的隐患；
4. **全天候高频精准防御**：将 45 分钟粗放超时提升为 15m/35m 两维阶梯风控，完美适配 Active 10 站 5 分钟高频发报现实。

### 3.2 下游任务与配置对齐要求
1. **Phase 2 执行文件 v1.3 修订**：
   - §5.2 的 Wunderground 切换窗、0.75h 阈值及截断下线条款正式作废，全面以此 ADR-0011 条款为准；
2. **配置落地（`default.yaml`）**：
   ```yaml
   risk_control:
     staleness:
       feed_heartbeat_timeout_minutes: 15.0  # 丢心跳撤销全部未成交挂单
       hard_staleness_hours: 0.5833         # 35 分钟绝对物理龄期全局熔断
       recovery_stable_minutes: 15.0        # 恢复健康稳定观察期
   ```
3. **接口契约固化**：
   - 明确 `OrderManager.cancel_all_open_orders()` 职责，与已成交仓位生命周期解耦；
   - `DynamicCorrector` 截断极值状态设为单向只增（TMAX）/只减（TMIN），禁止清空重置。
