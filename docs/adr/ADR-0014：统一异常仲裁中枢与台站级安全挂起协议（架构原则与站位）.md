# ADR-0014：统一异常仲裁中枢与台站级安全挂起协议（架构原则与站位）

- **状态**：Accepted
- **日期**：2026-09-20
- **裁决人**：量化工程团队
- **影响范围**：Phase 2 整体架构设计（执行文件 v1.3）、全系统异常处理模型、台站生命周期状态机

---

## 1. 背景与商业现实 (Context & Commercial Reality)

### 1.1 异常碎片化反模式的危害
在量化交易系统工程中，各业务子模块（数据接入、截断层、定价计算、订单执行、风控看门狗）各自编写局部兜底逻辑（如静默吞异常、盲目重试、私自降级）是导致系统在实盘极端行情下发生状态分裂（Split-Brain）和隐性穿仓的最主要根源。

### 1.2 商业假想敌与时延量纲定型
1. **假想敌定位**：本项目不与顶级做市商卷微波专线，目标对手盘是**缺乏高精实时气象算法、信息延迟达数十分钟的手工下注散户**，以及只赚买卖价差但在物理突变时调整迟钝的被动做市商；
2. **时延量纲回归物理现实**：系统运行于普通公网与云端环境，**全面废除不切实际的“毫秒级”幻想，系统容差与响应基准统一锚定为“秒级（5 ~ 10 秒级工程公差）”**。在分钟级交易周期上建立对散户的确定性信息与算法优势；
3. **Phase 2 核心使命**：以安全稳健的工程架构，实盘验证“散户对手盘是否存在、盘口深度几何、分钟级 Alpha 的实际容量大小”。

### 1.3 交易宇宙法定定义
本系统交易宇宙**严格且唯一限定于以下 10 个 Active 交易站点**：
`KORD, KLGA, KATL, KDAL, KSEA, KLAX, KHOU, KMIA, KSFO, KAUS`。
系统代码与配置中严禁为任何历史退役站保留半死不活的分支逻辑。

## 2. 核心架构原则 (Constitutional Principles)

### 原则一：控制面与数据面分离与“买单前双连通硬门禁” (Control/Data Plane Separation)
1. **数据面技术瞬态（Data Plane Faults）**：
   - 范围：公网单次 HTTP 抖动、连接瞬态重连、签名 Nonce 局部冲突等底层 I/O 扰动；
   - 自愈预算：底层模块就地退避重试的**总耗时预算严格限制在 30 秒以内**；
2. **买单前“数据新鲜度 + 网络连通”双硬门禁（Pre-Buy Gate Check）**：
   策略引擎在向网关下发市价买单的最后 1 秒，必须强制通过本地纯内存同步校验：
   ① **数据新鲜度**：所依赖的气温观测物理时间戳距离当前时间必须在受控预算内（$\Delta t_{\text{age}} \le 7.0\text{ 分钟}$，对应 Active 10 站 5 分钟发报周期 + 2 分钟传输宽限）；
   ② **网络连通性**：数据采集源与交易网关在最近的心跳中**确证处于连通状态**（非重试挂起态）；
   - **若任一不满足：本地直接物理打回买单意图（`REJECTED_STALE_DATA`），系统绝对静默，坚决不盲盒开仓**；
3. **控制面系统级 Incident（Control Plane Incidents）**：
   重试 30 秒超时、数据门禁击穿、COR 极值冲突等，立即升格为标准 `IncidentEvent` 移交中央中枢接管。

### 原则二：本地硬关阀与 Best-Effort 阻断定理 (Local Zero-Emission Theorem)
当中枢确认阻断时，在秒级公网现实下采取务实防御：
1. **本地硬关阀（Local Hard Valve Shutdown）**：本地内存发射阀瞬间关闭，从物理上切断所有对外发送买单的通路（本地绝对静默，任凭外部网络抖动，绝不漏发一个买单字节）；
2. **远端并发撤单（Best-Effort Cancel）**：并发向 Polymarket 发送 `cancel_all`。即便外部 API 因网络波动延迟或超时，由于本地已彻底锁死，系统绝不产生任何后续反手或加仓风险。

### 原则三：二元仲裁分类准则（作废 vs 挂起）
中央中枢依据 Incident 根因属性，对台站标的实施严格的“二元定性仲裁”：
1. **物理不可信 $\rightarrow$ 标的当日直接作废（Invalidate to EoD）**：
   - 判定标准：数据底层真实性遭破坏（如 COR 修正引发极值向下冲突、温度单步跳变 $>15.0^\circ\text{F}$ 等）；
   - 处置裁决：**彻底剥夺该站点今日交易资格，标的直接标记为 `INVALIDATED`，直至次日 00:00:00 物理复位前坚决禁止复活**；
2. **外部通信受阻 $\rightarrow$ 标的暂时安全挂起（Suspend with Cooldown）**：
   - 判定标准：传感器物理真实性未损坏，仅为外部公网传输超时或交易所网关暂时断流；
   - 处置裁决：标的置为 `SUSPENDED` 进入观察队列，严禁立即回弹，必须经受严格的**反振荡滞后恢复锁（Hysteresis Lock）**检验：
     - 必须满足强制静默冷却期；
     - 必须通过连续健康数据探针检验；
     - 一日内累计挂起满 3 次、或挂起跨越当地核心交易时间窗口，强制单向衰变为“当日作废”。

### 原则四：已成交资产绝缘与“交割日特别后门”原则
1. **通用铁律（禁止自动市价抛售自残）**：
   正常交易时段，链上已成交持仓（Filled Positions）物理不可逆。中枢严禁向订单簿发送自动市价平仓单，避免在 Polymarket 稀薄流动性下遭受掠夺性滑点；
2. **交割日特别后门条款（Settlement Grace Escape Hatch）**：
   在标的临近到期结算前的敏感窗口（如到期前 30 分钟），若触发异常或争议，持仓敞口处置权**自动降级移交至“风控策略层 / 人工介入通道”**，允许专业策略或人工依据残局深度进行定向对冲或人工干预，杜绝在结算关口机械锁死。

## 3. 全系统统一 Incident 契约标准（规范占位）

系统内所有子模块向中央中枢上报异常时，采用统一标准契约语言（不含任何具体代码实现）：

| 字段 | 语义约束 | 受控取值范围 / 规范 |
| :--- | :--- | :--- |
| `incident_id` | 全局唯一跟踪编码 | 标准 UUID / ULID |
| `timestamp_utc` | 物理发生时刻 | ISO 8601 UTC 标准时间戳 |
| `station_id` | 影响范围实体 | 限定 10 个 Active 交易站或 `GLOBAL` |
| `subsystem` | 报告源组件 | `INGESTION` / `TRUNCATION` / `PRICING` / `EXECUTION` / `SETTLEMENT` |
| `severity` | 严重级别 | `DEGRADED`（降级） / `CORRUPTED`（破坏） / `PANIC`（全局瘫痪） |
| `reason_code` | 受控原因枚举 | `SANITY_BREACH` / `DATA_STALENESS` / `COR_CONFLICT` / `EXCHANGE_DOWN` |
| `evidence_snapshot` | 现场只读快照 | 原始报文 / 异常堆栈 / 关键上下文摘要 |

## 4. 后果与系统演进影响 (Consequences)

### 4.1 架构收益
1. **贴合商业实战**：建立在分钟级对散户的信息优势基座上，摆脱虚假毫秒级束缚，秒级（5~10s）公差杜绝假报警重试震荡；
2. **杜绝盲盒下注**：买单前新鲜度与连通性双硬门禁，物理上消除了拿着过期数据开仓的隐患；
3. **权责明晰克制**：中枢管宏观阻断，数据面管底层重试，交割期留策略后门，整体设计安全而富弹性。

### 4.2 下游 Phase 2 实施界限
1. 本 ADR 为架构原则宪法，**坚决不引入任何具体实现代码，不侵入现有模块**；
2. 在 Phase 2 执行文件与任务分解中，设立专门任务统一规划并实现该中枢状态机与各模块的上报适配。
